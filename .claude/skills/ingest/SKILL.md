# Ingest Skill

你要处理高中语文作文 wiki 的原始输入。内容类型有两种：

1. **素材** — 人物事迹、事件、道理论据
2. **范文** — 完整作文，可能包含题目和写作指导

单个原始文件可能**同时包含**两种类型（如范文与配套素材打包在一起，或包含多个不同类型内容的文档）。

## 目录权限界定

本仓库各目录有不同的操作权限，ingest 过程中必须严格遵守：

| 目录 | 权限 | 说明 |
|------|------|------|
| `raw/` | **只读** | 原始资料，禁止修改或删除其中任何文件 |
| `raw/archive/` | **只写（移动）** | 仅通过 `mv raw/{file} raw/archive/` 移入，禁止直接编辑归档内容 |
| `wiki/material/` | 读写 | 素材页面创建与更新 |
| `wiki/essay/` | 读写 | 范文页面创建与更新 |
| `wiki/topic/` | 读写 | 主题页面创建与更新 |
| `wiki/index.md` | 读写（合并更新） | 主索引，按条目增/改，不可覆盖整文件 |
| `wiki/material/index.md` | 读写（合并更新） | 素材索引，按条目增/改，不可覆盖整文件 |
| `wiki/issues/` | 读写 | 素材矛盾冲突问题报告，按需创建 |
| `wiki/log.md` | **追加** | 操作日志，只允许追加新行，禁止修改已有行 |
| `templates/` | **只读** | 模板文件仅作参照，禁止修改 |

## 强制性规则

以下规则在 ingest 全程具有最高优先级，任何情况下不得违反：

1. **raw 只读不改**：`raw/` 下文件只能通过处理完毕后的 `mv` 移入 `raw/archive/`，处理期间不得在原地修改或删除。
2. **范文原样搬运**：范文「全文」章节必须逐字复制，禁止增、删、改任何字符。
3. **写作指导零 AI**：「写作指导」内容只能来自 raw 中的原始文字，禁止 AI 自行编写或补充；如果 raw 中无写作指导，该章节不创建。
4. **模板只读**：所有新页面必须参照 `templates/` 下对应模板创建，模板文件本身禁止修改。
5. **log.md 追加**：`wiki/log.md` 只追加新行，不改已有行。
6. **双链完整**：所有页面间关联必须使用 `[[双链]]` 语法，确保双向链接存在（创建链接前检查目标页面是否存在，不存在则先创建）。
7. **索引合并**：更新 `wiki/index.md` 和 `wiki/material/index.md` 时，按条目分别合并（已有条目内容相同则跳过，有差异则更新，不存在则新增），禁止覆盖整个索引文件。
8. **命名规范**：
   - 素材：本名命名，无修饰语（如 `苏轼.md`，不写 `宋代诗人苏轼.md`）
   - 主题：四字或六字短语（如 `家国情怀.md`）
   - 范文：`来源-作文标题.md`，无来源则只用标题
9. **AI 补充标识**：作文原子化拆分时，素材的「关键事迹」「事件经过」等事实性条目必须来自作文原文。若条目由 AI 基于通用知识库或联网搜索补充（非原文内容），必须在该条目最前面标注 `【AI】` 前缀，例如：
   ```
   - 【AI】苏轼晚年被贬海南，仍坚持办学教化百姓。
   ```
   无 `【AI】` 前缀的条目视为来自原文，禁止混入 AI 编造的内容。
10. **矛盾冲突处理**：若导入的素材与已有素材存在事实性矛盾（如事件时间线冲突、人物行为互斥、数据矛盾等），必须：
    - 在素材页底部追加 `## 矛盾冲突` 章节，原封搬运冲突双方的原文内容以便对比，并阐述具体矛盾点
    - 在 `wiki/issues/{素材名}-矛盾冲突.md` 创建问题报告，内容包含：涉及素材、冲突描述、双方原文、建议处理方式

## 文件选择

- **用户指定了文件**（通过 `@file` 或路径）：只处理该文件。
- **未指定文件**：列出 `raw/` 下的文件（排除 `raw/archive/`），处理所有新文件。
- 处理完成后，将文件移入 `raw/archive/`。

## 处理逻辑

读取原始文件，判断内容类型。对每种类型执行下方对应的工作流。如果同时包含两种类型，先处理素材，再处理范文（因为范文工作流需要引用素材）。

---

## 素材 Ingest

### 第一步：读取与分类

读取素材内容，判断子类型：**人物** / **事件** / **道理**。

### 第二步：创建素材页

根据素材类型，在 `wiki/material/{素材名称}.md` 中使用对应模板。

**合并规则：**
- 如果素材页**不存在**：按下方模板创建
- 如果素材页**已存在**：合并，保留已有内容并补充新信息（如新增关键事迹、使用示例、关联素材）

参照 `templates/material-template.md` 中对应的子类型模板（人物/事件/道理）创建素材页。该模板定义了完整的 frontmatter 字段和章节结构。

关键约束：
- `type: 素材`、`subtype: 人物 | 事件 | 道理`、`title` 必填，`tags: []`
- 素材名称用本名，不用修饰语（如 `苏轼.md`，不写 `宋代诗人苏轼.md`）
- 事件/道理用简洁描述性名称

### 第二步附：冲突检测

如果素材页已存在（合并场景），将新素材的关键事迹/事件经过与已有内容逐条比对。若发现事实性矛盾（如时间、行为、数据互斥），执行以下操作：

1. 在素材页**底部**追加 `## 矛盾冲突` 章节，按以下格式：

```markdown
## 矛盾冲突

### 冲突 1：{矛盾点简述}

**已有内容：**
> {原封搬运已有页面的原文条目}

**新导入内容：**
> {原封搬运新素材的原文条目}

**冲突分析：**
{阐述双方的具体矛盾，为什么无法同时成立}
```

2. 在 `wiki/issues/{素材名}-矛盾冲突.md` 创建问题报告：

```markdown
---
type: issue
related_material: [[素材名]]
date: YYYY-MM-DD
status: pending
---

## 冲突描述

{概括矛盾}

## 双方原文

### 已有内容
> ...

### 新导入内容（来源：{范文文件名或 raw 文件名}）
> ...

## 建议处理

{建议核实来源、保留较可靠的一方等}
```

冲突检测不阻塞素材页创建——先完成合并，再追加 `## 矛盾冲突`，再创建 issue 报告。

### 第三步：更新主题页

扫描 `wiki/topic/` 下已有的主题页。如果某主题与该素材相关，在该主题页的"关联素材"中添加链接。

### 第四步：更新素材索引

编辑 `wiki/material/index.md`，在对应类型（人物/事件/道理）下更新或新增条目。根据素材类型使用对应字段名。

**合并规则：**
- 如果索引中**不存在**该素材名：新增条目
- 如果索引中**已存在**该素材名且内容相同：跳过
- 如果索引中**已存在**该素材名但内容有差异：合并，保留已有信息并补充新内容（如新增可用主题、关联文章）

**人物型：**
```markdown
### 素材名
**人物简介**
...
**关键事迹**
...
**可用主题**
[[主题]]
**关联文章**
[[文章]]
```

**事件型：**
```markdown
### 素材名
**事件简介**
...
**事件经过**
...
**可用主题**
[[主题]]
**关联文章**
[[文章]]
```

**道理型：**
```markdown
### 素材名
**道理阐述**
...
**可用主题**
[[主题]]
**关联文章**
[[文章]]
```

### 第五步：更新主索引

编辑 `wiki/index.md`，在"素材"分类下更新或新增一行：

```markdown
- [[素材名]] — 简介 | 可用主题
```

如果该素材条目已存在且内容相同则跳过，有变化则更新。

## 范文 Ingest

### 第一步：读取

读取原始文件中的范文内容。

### 第二步：创建范文页

创建 `wiki/essay/{来源-作文标题}.md`，参照 `templates/essay-template.md` 创建范文页。如果范文页已存在，合并内容（保留已有分析，补充新信息）。

命名规则：
- 有来源（考试作文）：`来源-作文标题.md`（如 `2024全国甲-选择与担当.md`）
- 无来源（非考试作文）：只用标题（如 `青春与责任.md`）

**硬性规则：**
- "全文"部分必须原样搬运，禁止任何改动
- "写作指导"部分只允许来自 raw 中的原始内容，如果没有则不写此节，禁止 AI 自行编写

### 第三步：提取素材

识别范文中使用的所有素材。对每个素材：

- 如果素材页已存在（`wiki/material/`）：追加使用示例。同时检测范文中的素材事实与已有素材页是否存在矛盾冲突（参照「素材 Ingest → 第二步附：冲突检测」），如有冲突则追加 `## 矛盾冲突` 并创建 issue
- 如果不存在：创建新的素材页

使用示例格式（追加到已有素材页的"使用示例"中）：

```markdown
### [[主题名称]]-[[来源]]
> 原文引用（从范文中提取的具体段落）
```

### 第四步：创建或更新主题页

如果范文带有题目或写作指导，识别主题。参照 `templates/topic-template.md` 创建或更新 `wiki/topic/{主题}.md`。

命名规则：主题用四字或六字短语（如 `家国情怀.md`、`个人成长.md`）

### 第五步：更新素材索引

更新所有涉及素材的 `wiki/material/index.md` 条目，刷新"关联文章"字段。

### 第六步：更新主索引

编辑 `wiki/index.md`：
- 在"范文"下新增：`- [[范文]] | 主题：xxx | 素材：[[xxx]], [[xxx]]`
- 如果创建了新主题，在"主题"下新增：`- [[主题]] | 关键词：xxx`

---

## 收尾：归档与日志

**无论本次处理了几种类型，以下步骤只执行一次。**

将原始文件移入 `raw/archive/`：

```bash
mv raw/{filename} raw/archive/
```

追加 `wiki/log.md`，按实际处理的内容类型逐行记录：

```markdown
## [YYYY-MM-DD] ingest 素材 | 素材名 — 一句话说明
## [YYYY-MM-DD] ingest 范文 | 来源-标题 — 一句话说明
```

## 交叉引用规则

所有关联使用 Obsidian `[[双链]]` 语法，维护双向链接：

| 关联 | 方向 | 位置 |
|------|------|------|
| 素材 ↔ 主题 | 双向 | 素材"可用主题" ↔ 主题"关联素材" |
| 素材 → 素材 | 通过"关联素材" | 素材"关联素材"并写明关联理由 |
| 范文 → 素材 | 范文链接素材 | 范文"关联素材" |
| 主题 → 范文 | 主题链接范文 | 主题"范文参考" |
| 素材 → 范文 | 通过"使用示例" | 素材"使用示例"中 `[[来源]]` 链接范文 |

创建链接时，检查目标页面是否存在。如果不存在，先创建该页面。
